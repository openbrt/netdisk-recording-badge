# 录音续航与侧边指示灯测试方案

## 范围与当前状态

本方案通过短时电池录音、工牌自动遥测和后台进程估算续航，并探索低亮度录音指示灯。完整放电和八小时稳定性测试作为可选后续验证，不再作为首次估算的前置条件。测试遥测和[私有后台](../../../tools/endurance/README.zh_CN.md)已经实现；2026-10-06 电量曲线结果及限制另见[录音续航](../../recording-endurance.zh_CN.md)。应用与硬件基线见[操作指南](../../kuku-badge-user-guide.zh_CN.md)、[硬件规格](../../hardware-design/specifications.zh_CN.md)和[固件布局](firmware-layout.zh_CN.md)。

当前应用采用 16 kHz、16 bit、单声道 PCM，每 60 秒保存分段并上传已完成文件。录音时约 15 秒无按键操作后，背光降为 15%；录音按键处理不支持长按下键熄屏。断网结束采集，恢复联网只补传，不自动恢复录音。依据：[应用定义](../../../main/kuku_app.h)、[按键与空闲处理](../../../main/main.c)、[采集与写入](../../../main/kuku_rec.c)、[上传调度](../../../main/kuku_baidu.c)。

PCM 每秒产生 32,000 字节，每个完整分段包含 1,920,000 字节音频，每小时 115.2 MB，不含文件头。5 MiB 原始存储分区最多对应 163.84 秒；文件系统、已有文件和写入安全余量会缩短它。成功上传并释放本地空间必须跟上采集，长期有效音频净吞吐需超过 256 kbit/s，并为建连、协议和重试留余量。当前格式与分区不适合等数分钟后再集中上传。

## 1. 侧边指示灯探索

2026-10-05 核对的证据：

| 证据 | 支持的结论 | 边界 |
| --- | --- | --- |
| [官方首次使用指南](https://ai-passport.folotoy.cn/guides/getting-started/)描述绿灯充电时亮、充满后灭 | 官方定义的用途是充电指示 | 没有给出接线或 PWM 控制方式 |
| 本地[引脚定义](../../../components/bsp/include/bsp_pins.h)和 BSP | 屏幕背光有明确控制接口，独立侧灯没有 | 软件未定义不等于物理上绝对没有接线 |
| 官方小智[板级配置](https://github.com/FoloToy/folo-ai-passport-xiaozhi/blob/72da544d1b51678f5d88967adc299b3aec956946/main/boards/folotoy/ai-passport/config.h)与[板级实现](https://github.com/FoloToy/folo-ai-passport-xiaozhi/blob/72da544d1b51678f5d88967adc299b3aec956946/main/boards/folotoy/ai-passport/ai_passport_board.cc) | 没有配置状态 LED，也没有覆盖 `GetLed()` | 这是另一款固件的实现，不是电路图 |
| 其[板级基类](https://github.com/FoloToy/folo-ai-passport-xiaozhi/blob/72da544d1b51678f5d88967adc299b3aec956946/main/boards/common/board.cc#L56)返回 `NoLed`，中间的 `WifiBoard` 也未覆盖 | 该官方固件没有实现侧灯控制路径 | 电气可控性仍未验证 |

当前判断：由充电电路控制的指示灯是合理推测，但尚未确立程序控制能力。不通过猜测或遍历未定义 GPIO 来找灯。

按以下顺序探索：

1. 确认实际灯的位置、颜色、板卡版本。印刷状态图例或产品渲染图不能证明接线。
2. 分别观察应用开机并 USB 充电、硬件关机但仍充电、充满电、纯电池供电时的灯光，外部记录现象。应用关闭时仍工作的灯支持硬件自主控制判断，但不能排除共享控制连接。
3. 获取匹配版本的原理图或厂家引脚定义。无法取得时，另行实物检查，追踪 LED 与电阻连接到充电芯片状态输出、MCU 还是其他驱动。通断追线在 USB 和电池均断开时进行；开壳和探测属于单独的实物工作，本方案未执行。
4. 记录控制器/引脚、有效极性、电阻与电流路径、共享连接，以及是否支持调光。即使接到 MCU，也需要确认空闲电平和控制电路。
5. 若可控，将已确认接口纳入 BSP，验证关闭、低亮度与短闪，同时不影响充电、音频或其他引脚所有者。若仅由充电芯片控制，增加独立录音灯需要硬件改动。屏幕背光短闪是另一种替代方案，不能算侧灯可控的证据。

待硬件确认后的建议灯效：最低稳定可见亮度，每 3 秒亮约 100 毫秒。依据录音状态与近期 PCM 采集/写入确实前进来驱动，而不只检查任务标志；停止录音或检测到故障后停止闪烁。验证时序、可见性、电流成本与采集互不干扰，使用不阻塞的任务/定时器路径。不能根据灯的占空比直接推算整板节电比例。

## 3. 共同准备与自动开始

1. 绑定实物工牌、准确的固件镜像/ELF 身份、分区和源码/配置。使用有效云端应用配置，不能用公开门禁的占位凭据。需要更新时遵循兼容分段烧写政策，保留 NVS 与录音。
2. 完成 Wi-Fi/网盘授权和校时，等待待传文件上传完毕，检查空间超过一个完整分段加写入余量。不删除未同步录音。比较各模式时固定 AP/位置、网络、环境、照片/素材及音频负载。
3. 启动工牌能通过 Wi-Fi 访问的私有后台收集进程。测试地址及设备鉴权私下配置，不公开端点密钥。后台自动保存遥测并生成滚动报告。USB 串口只用于准备，拔线后通过无线继续上报。
4. 正常充电，确认此前亮起的充电灯随后熄灭。记录初始电量/电压及充电历史；电量百分比本身不能证明充满。各轮采用相同静置流程。播放固定、无私人内容的标记音轨，并记录独立时钟，以检查音频。
5. 通过支持数据的 USB 线连接保持唤醒的电脑，明确开启本次测试待触发状态。主机连接稳定 10 秒后，连接转为断开且持续 5 秒，产生 `usb_host_detached` 事件，携带设备单调时钟、启动/会话编号、电量/电压及录音状态。这些时长是待实机验证的防抖设计值。通过 Wi-Fi 立即发送，后台确认接收并自动开始观察；拔线后不依赖 USB 串口。
6. 已在录音时直接开始测量，不重新启动采集。未在录音时上报 `waiting_for_recording`，通过正常实体录音手势开始，`recording_started` 事件确定可用于估算的录音区间。拔线本身不自动打开麦克风。不要使用 `REC 28800`：现有诊断命令最多 600 秒，应走正常应用录音路径。

[ESP-IDF 5.5.3 主机检测](https://github.com/espressif/esp-idf/blob/v5.5.3/components/esp_driver_usb_serial_jtag/include/driver/usb_serial_jtag.h)依据 USB SOF 数据帧。它检测数据主机，不检测 VBUS 电源或充电：充电器/充电宝不会被识别为已连接，电脑休眠或数据中断也可能在仍供电时显示断开。因此首次测试限定为保持唤醒的电脑，并且实际完全拔线，记录这一操作条件。接纳数据前验证插拔、关闭串口行为，以及主机休眠/数据丢失的歧义。重新插线中断估算；无 USB 开机不伪造拔线事件。通用充电器拔线识别需要确认 VBUS/充电状态接口，目前板级引脚未定义。不能靠电压下降猜拔线，也不猜测 GPIO。

## 4. 无线遥测与后台进程

已实现的测试接口为 `ENDURANCE ARM <url> <token>`、`ENDURANCE STATUS` 和 `ENDURANCE OFF`；配置与协议见[后台指南](../../../tools/endurance/README.zh_CN.md)。在工作任务中每 10 秒通过既有共享 I2C 管理读取[电量和电压](../../../components/bsp/src/bsp_battery.c)，不唤醒屏幕、不改变亮度。当前 SOC 接口返回整数百分比；虽然读取两个寄存器字节，仍丢弃小数字节。增加采样次数不等于取得经过校准的高精度容量数据。

每分钟将六个样本通过带鉴权的 Wi-Fi 请求批量上报，尽量复用连接。拔线、开始/停止录音、重新插线和故障立即上报事件。网络/I2C 操作不阻塞采集、按键回调或 LVGL。32 项 RAM 队列加六个待确认样本、序号、接收确认、幂等重试和有上限的退避避免重复事件与无限积压。记录丢样和迟到；遥测让位于音频上传，不改变已有上传的 Wi-Fi 省电策略。各模式采用相同开销，并测量额外负载；量化前，估算对应包含遥测的工作负载。

| 字段 | 用途 |
| --- | --- |
| 测试/设备匿名编号、启动编号、会话编号、模式、固件身份、样本序号 | 区分轮次、复位、重试和可比版本 |
| 单调采样时间、可选 UTC、后台接收时间 | 使用设备采样时间拟合，不能把传输延迟当电量变化时间 |
| 主机连接状态、拔线检测来源、测试待触发状态、电源来源可信条件 | 区分受控拔线测试与未知充电状态 |
| SOC %、电池 mV、读取有效标志 | 电量趋势；读取失败记为无效，不当作 0% |
| 录音状态、64 位 PCM/采样进度、分段序号、停止原因 | 确认实际采集前进，不仅看任务标志或会回绕的字节计数 |
| 实际背光值/模式、Wi-Fi 状态/RSSI、上传积压、空间、可取得的堆/复位信息 | 排除负载变化，分类故障 |

后台追加私有 JSONL/CSV，按序号去重，每分钟更新报告。连续三个上报周期未收到消息时标记遥测过期并冻结最后估算；消息缺失不能证明电量耗尽。分段到达仅作为辅助证据，因为上传延迟可变。复位创建新的启动区间。停止、插线、模式变化或采集/上传故障关闭可用于拟合的区间并记录原因。遥测中断不能强制停录；当前应用本身的断 Wi-Fi 停录行为仍如实记录。补传拔线事件保留原始时间，不能重新开始后台计时。

实机使用前，主机检查应覆盖待触发/防抖/插线/复位状态转换、无效电量、量化/平坦/噪声曲线、丢失/迟到/重复上报和录音故障。设备检查确认实际拔线后无线持续上报、屏幕行为不变、采集不受影响。后台部署私下按测试配置，维护文档不保存地址或密钥。

## 5. B1：短时观察与续航推估

1. 自动收到拔线/开始事件后，不操作屏幕，保持录音。后台先收集 30～60 分钟。排除拔线及开始录音后至少前 5 分钟，以减少充电和负载切换瞬态；若读数仍恢复或上升，延长排除区间。
2. 使用排除期后至少 30 分钟、负载不变且健康的连续电池录音区间。要求电量至少下降 10 个百分点、有效样本达到预期的 90%，且没有超过两分钟的采样空档。满电百分比平台不能支持推算，应等待可用下降。这些是初始工程质量门槛，不保证电量计精度。
3. 对有效样本拟合 `SOC(t) = a - r × t`，时间单位为小时，`r > 0`，单位为百分点/小时。比较前后半区间斜率，以及稳健拟合与普通拟合；差异超过 25%、持续上升或无法解释的电量突变时，标记趋势不稳定/数据不足。保留被排除的数据和理由。不跨越插线、复位、模式改变、停录或网络/存储故障拟合。
4. 采用明确的报告保留电量 `S_reserve = 10%`，计算 `T_remaining = max(0, S_now - S_reserve) / r` 和满电等效时长 `T_full = (100 - S_reserve) / r`。10% 是估算/报告约定，不是已经实现的停录阈值，也不是实测关机点。可另外展示推算到 0% 的值。不能把未观察到的初始满电平台加成实测录音时间，也不单靠电压下降线性换算容量。
5. 仅举算术例子：有效区间 40 分钟下降 12 个百分点，则 `r = 18 点/小时`；估计满电到保留 10% 可录 5 小时，到 0% 约 5.6 小时。这不是工牌实测结果。比较模式时使用相同保留电量和可用 SOC 区间。
6. 报告拟合区间、电量范围、耗电速度、实际校验音频时长、最新电量、预计剩余/满电时长和负载。敏感性范围采用前后半区间/稳健斜率，以及端点电量下降额外按 ±2 个百分点保守浮动后的斜率，取正斜率对应的时长上下界。允许斜率达到零时，不给有限上界。这是模型敏感性范围，不是统计置信区间；未包含电量计/profile 未校准偏差，以及未来负载/低电量变化。独立电池验证前 SOC 校准仍未确认。
7. 满足质量门槛，且至少跨度 10 分钟的连续三次报告中预计范围变化小于 15%，即可结束。到 60 分钟仍不满足时，后台说明缺失条件；可以在短观察有价值的范围内继续，也可以以数据不足结束，不强制放到没电。正常停录，等待最后 WAV 上传，保留故障而不悄悄重新开始。提前停录是可靠性问题，不能当作电池续航估算。

短时 SOC 斜率推估的是当前负载下的续航，不能证明预测时长内一直稳定录音、容量已经校准或实际关机时刻。可选 U1/D1 分别验证这些问题。比较模式使用匹配短区间，仅在模型范围或条件变化妨碍有效比较时追加轮次。

## 6. WAV 与切段验证

每次测试后列出实际日期目录，独立下载全部测试分段。使用真实日期与文件名；跨午夜测试覆盖两天目录。例如：

```text
tools/bdverify/bdverify ls YYYY-MM-DD
tools/bdverify/bdverify get YYYY-MM-DD/RECORDING.WAV
tools/bdverify/bdverify md5 YYYY-MM-DD/RECORDING.WAV
```

按预期远端路径与文件内容去除重试重复。逐个检查下载 WAV 的 RIFF/WAVE 头、采样率、声道、位深、实际长度与声明长度、偶数字节音频长度和解码采样数。完整分段应有 960,000 个单声道采样，最后一段可较短。唯一分段的解码采样总数除以 16,000，得到有效录音时长 `T_audio`。正常短测记录最后完成并上传的分段；若另做可选断电测试，则区分关机前上传和接电恢复后的音频。

独立计算下载内容的 MD5 能标识返回字节；只有另有独立本地摘要或字节参考时，才能证明本地与云端相同。不能只用云端元数据 MD5 字段。当前上传成功后的自动清理可能移除本地文件，完整本地/云端摘要比对需要单独仪器化或已有保留的本地参考。

将录下的连续标记音轨与外部参考对齐，考虑两个时钟的缓慢漂移；排查任何确证的缺失或重复音频，不能把时钟漂移算成切段缺口。拼接试听，并检查每个边界前后至少两秒。文件头正确、文件数量符合或振幅非零，都不能单独证明麦克风连续采集。

## 7. 可选的电池端电流与灯光测量

诊断优化收益时，在已确认的电池供电路径上接入合适功耗分析仪，并核对全部供电路径。接电池线路或开壳需另行确认实物方案，文档任务未执行这些操作。避免仪器压降或其他供电路径改变设备行为。

对比测量：纯电池空闲熄屏、15% 背光录音、B2 实现后的零背光录音、上传突发、B3 指示灯短闪。记录电压、平均电流、采样率/带宽和温度；低采样率仪表不能声称测到了真实 Wi-Fi 峰值。积分电流得耗电量，积分电压乘电流得能量。估算续航应使用整板电池端平均电流，不能套用芯片数据手册的休眠电流。

B3 与 B2 对比一个闪灯周期的额外电量/能量。分别检查手动停录、断网停录、空间停录、采集故障时灯效是否停止；PCM 不再前进后，不能继续提示健康录音。检查低电量可见性与充电指示共存；仅从可比测试量化续航差异。

## 8. 结果与验收

后台报告包括测试/固件/模式身份、拔线事件与电源来源假设、初始电量/电压、有效采样区间、有效/缺失数量、电量下降/速度、保留电量约定、预计剩余/满电时长及敏感性范围、`T_audio`、WAV/边界结果、上传/积压、停止/故障原因和观察开销。原始遥测及音频私下存放。

| 问题 | 验收/报告规则 |
| --- | --- |
| 拔线后是否自动开始收集？ | 已待触发且已确认的电脑拔线产生一个已确认接收的事件；无线样本继续，屏幕行为不变，采集不受影响。主机休眠/仅数据断开属于歧义，不能当作已确认 VBUS 拔线 |
| 短时数据能否推估续航？ | 满足第 5 节质量/稳定性门槛，报告估算、敏感性范围、保留电量及假设；平坦/无效/不稳定时报告数据不足 |
| 观察期间录音是否健康？ | 样本及下载 WAV 在实际区间内持续前进，无确证音频间隙/重复/损坏、非预期停录/复位或持续增长的未处理积压 |
| 熄屏是否更好？ | 同条件比较 B2/B1 耗电速度与推估范围；不确定范围重叠时不能确定优胜者 |
| 录音灯是否可用？ | 先确认接线；B3 提示近期健康采集并在故障后停止，采用可比遥测/电流成本 |
| 是否已实测满电续航？ | 只有可选 D1 到达有证据支持的电池终点才成立；B1 仍是外推 |

首次执行顺序：实现并验证待触发拔线事件、无线遥测和后台收集器；执行一次 B1 短测，数据合格即输出估算；按需要比较已实现的 B2/B3。侧灯接线探索独立进行。八小时 U1 和三次完整放电不再是前置条件。遥测已实现并通过主机测试；实际拔线/上报验收单独记录。已有通过门槛的电量曲线估算，见[录音续航](../../recording-endurance.zh_CN.md)；满电续航直接实测与侧灯电气控制仍需对应测试验证。
