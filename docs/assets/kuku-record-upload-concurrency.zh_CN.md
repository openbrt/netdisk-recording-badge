# 网盘录音工牌录音与上传并发

2026-10-02，在 ESP32-C3 工牌上验证应用 v0.3.9。
实现后的操作见[用户指南](../kuku-badge-user-guide.zh_CN.md)。

## 运行时职责

- 本文记录 v0.3.9 的历史验收；新版持续录音操作以用户指南为准。
- 当时有待传录音或正在上传时，也可以开始新录音。仍要求已连接 Wi-Fi、已授权，以及至少 256 KB 空间。空间不足时保存较短的片段，单段两分钟上限不变。
- 采集任务优先级为 12，文件写入为 10，上传为 4。8 KiB PCM 队列在 16 kHz、16 位单声道下约能缓存 256 ms。溢出会报错并结束片段，不静默继续。
- 录制中写入 `.REC`，完成 WAV 头并关闭文件后，在目录互斥锁内发布为 `.WAV`。上传只读取已发布文件。开机时修复具有有效 WAV 头的中断 `.REC` 文件，再发布，不覆盖已有 `.WAV`。
- 每批上传复制文件名形成快照。新录音发布、上传完成后的改名都不会移动本批索引。上传期间保存的新录音请求下一批，任意时刻只有一个上传任务拥有队列。
- 目录操作使用目录互斥锁，PCM 读取和 HTTPS 都不持有它。独立文件句柄之间的文件系统同步由 FatFs 提供。
- 已有上传时，录音启动复用当前网络和授权状态，不额外建立 TLS 探测连接。单独启动录音仍检查两个网盘主机。上传失败保留已关闭文件等待重试，不取消采集。

## 内存配置

前几轮实机测试出现并发时 RSA/TLS 内存分配失败。最终配置采用动态 TLS 缓冲，接收记录上限保持 16 KiB，发送上限为 2 KiB；上传按 1 KiB 分块；Wi-Fi 使用四个常驻 RX 缓冲、限制动态收发缓冲，TCP 窗口为 2880 字节。保留已测量需求的 12 KiB 上传栈，不需要网络探测的启动任务使用 4 KiB 栈。Flash 写入期间 I2S 中断仍可执行。

并发心跳观察到空闲堆 22052 字节，最大连续块 7680 字节。`min=464` 是 ESP-IDF 各内存区域历史最低值的总和，不是某个瞬间的总空闲堆快照。本轮短测试未证明所有网络和文件系统条件下的最坏分配余量。

## 重跑专项实机检查

工具会复位选中的工牌，创建两段测试录音，并使用正常的自动网盘上传流程。不擦除配置，不发出文件删除命令。需要 pyserial、ffmpeg、选中的 USB 摄像头，以及已经联网/授权的工牌。

```bash
python3 tools/test_kuku_parallel_device.py \
  --port /dev/cu.usbmodem212101 \
  --output /tmp/passport-parallel-check \
  --elf-prefix 85a5571c3
```

未验证：实体双键 ADC 识别、标定音质、两分钟/满存储/长时间压力测试、任意 RF 环境，以及真实断电恢复。主机恢复和故障注入结果与这些实机检查分开报告。
